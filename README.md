# Machine Learning Course — Teacher Edition

![License: All Rights Reserved](https://img.shields.io/badge/License-All%20Rights%20Reserved-red.svg)

Lecture notes, slide decks, example notebooks, **teacher practical notebooks with solutions**, **teaching cheat sheets**, and a private **quiz bank with answer keys** for an introductory machine learning course.

This is the **private teacher repository**. It mirrors the [public student repository](https://github.com/DerAndr/machine_learning_course_basics) and adds teacher-facing assets for every practical session plus a private assessment-authoring layer.

The repository is organized lecture by lecture and is meant to work both as:

- a course library for students who want to read notes and browse examples
- a local notebook workspace for students who want to run materials with `uv`
- a **teacher reference** with solved practicals, teaching cheat sheets, quizzes, and answer keys
- a source repository for the interactive textbook and its agent-readable knowledge bundle

## Private Teacher Layer

The public student repository is the source of truth for student-facing lecture materials.
This private repository adds and maintains the teacher-only layer:

- solved practical notebooks in `lectures/<lecture_slug>/practical_session/*_teacher_90min.ipynb`
- teaching cheat sheets in `lectures/<lecture_slug>/practical_session/teacher_cheat_sheet.md`
- theory and practice quiz sources in `quizzes/`
- reproducible practice-quiz answer keys in `quizzes/answer_keys/`
- private publishing and maintenance documentation in `README.md`, `AGENTS.md`, and selected files under `docs/`

## Start Here

If you are a **teacher** preparing a lecture:

1. Open `lectures/<lecture_slug>/practical_session/teacher_cheat_sheet.md` — teaching goals, recommended 90-minute flow, expected takeaways
2. Open the teacher notebook listed in the lecture README — the solved notebook or demo notebook you will demonstrate
3. Review the student practical notebook when one exists — the version students receive (TODO cells with no solutions)
4. Read `lectures/<lecture_slug>/lecture_notes.md` for recap context
5. Open `lectures/<lecture_slug>/slides/lecture.pdf` when the lecture has a packaged slide deck
6. If you need assessment material, open the matching files in `quizzes/theory/` and `quizzes/practice/`

If you are a **student**, you can:
1. Use your local AI agent (via the `.agents/skills/ml-course-student-navigator/` skill) to help you navigate materials and troubleshoot environments.
2. Open the [interactive textbook](https://derandr.github.io/machine_learning_course_basics/) for the guided concept layer.
3. Open `lectures/README.md` for the full lecture map.
4. Choose a lecture directory.
5. Read `lecture_notes.md`.
6. Open `slides/lecture.pdf` when the lecture has a packaged slide deck.
7. Run notebooks from `lecture_examples/` if needed.

If you are a **student**, follow `docs/student-quickstart.md`.

For local setup:

```bash
uv sync
uv run python tools/check_notebook_environment.py
uv run jupyter lab
```

Student-oriented setup instructions live in `docs/student-quickstart.md`. For heavy deep learning workloads, read `docs/deep-learning-colab-guide.md`.

To improve the interactive textbook, start with `docs/contributing-to-textbook.md`.

## Local Setup

Use `uv` as the single environment manager for this repository.

1. `uv sync`
2. `uv run python tools/check_notebook_environment.py`
3. `uv run jupyter lab`

There is no separate `requirements.txt` on purpose.

- `pyproject.toml` is the source of truth for dependencies.
- `uv.lock` is the reproducible lockfile.
- The default environment installs the shared baseline used across the course.
- Heavy or lecture-specific packages can be added only when needed:
  - `uv sync --group ensembles` for Lecture 07 extras such as `catboost`, `lightgbm`, and `xgboost`
  - `uv sync --group time_series` for Lecture 08 extras such as `prophet`
  - `uv sync --group hpo_automl` for Lecture 10 extras such as `h2o`, `optuna`, `hyperopt`, and `scikit-optimize`
  - `uv sync --group neural_networks` for Lecture 12 extras such as `torch` and `torchinfo`
  - `uv sync --group nlp` for Lecture 16 extras such as `transformers`, `sentence-transformers`, `datasets`, and `gensim`
  - `uv sync --group llm` for Lecture 18 extras such as `accelerate`, `peft`, `outlines`, and current `transformers`
  - `uv sync --group xai_piml` for the optional PiML example in Lecture 11 on compatible Python versions
  - `uv sync --group ml_in_production` for Lecture 14 extras such as `evidently` and `mlflow`

## Working With Lecture Examples

- Each lecture example notebook in `lecture_examples/` has a paired `.py` file.
- The `.py` files are generated companions for local reading, diffing, and lightweight execution.
- If a notebook contains Colab-only install cells such as `!pip install ...`, those cells can usually be skipped locally after `uv sync`.
- When a lecture uses optional heavy dependencies, install the matching group first and then re-run the environment check:
  - `uv run python tools/check_notebook_environment.py --group ensembles`
  - `uv run python tools/check_notebook_environment.py --group time_series`
  - `uv run python tools/check_notebook_environment.py --group hpo_automl`
  - `uv run python tools/check_notebook_environment.py --group neural_networks`
  - `uv run python tools/check_notebook_environment.py --group nlp`
  - `uv run python tools/check_notebook_environment.py --group llm`
  - `uv run python tools/check_notebook_environment.py --group ml_in_production`
- To regenerate the `.py` companions and example READMEs after changing notebooks, run:
  - `uv run python tools/sync_lecture_examples.py`

## Working With Quizzes

- `quizzes/theory/` contains multiple-choice quizzes for Google Forms, with correct answers marked for the teacher copy only.
- `quizzes/practice/` contains code-backed quiz prompts for numeric or short free-response answers.
- `quizzes/answer_keys/` contains Python scripts that reproduce expected practice answers.
- `tools/convert_quiz_dumps.py` converts archived Google Forms JSON dumps into the normalized Markdown quiz format used in this repository.
- Never publish the Markdown quiz files verbatim to students because they contain answer markers or answer explanations.

## Relationship to the Public Student Repository

This teacher repository is linked to the public student repository via an `upstream` remote:

| Remote | Repository | Visibility |
|--------|-----------|------------|
| `origin` | `machine_learning_course_teacher` | **private** |
| `upstream` | `machine_learning_course_basics` | public |

### Teacher-only files

These paths exist **only** in this repository or are intentionally maintained here with teacher-specific content:

- `practical_session/<name>_practical_teacher_90min.ipynb` — solved teacher notebooks
- `practical_session/teacher_cheat_sheet.md` — teaching quick-reference
- `quizzes/theory/*.md` — theory quiz source files with teacher answers
- `quizzes/practice/*.md` — practice quiz source files
- `quizzes/answer_keys/*.py` — reproducible answer-key scripts
- `tools/convert_quiz_dumps.py` — quiz-import normalization helper
- `README.md`, `AGENTS.md`, `docs/publishing-model.md`, `docs/repository-overview.md` — private-repo maintenance documentation

Student-facing lecture content under `lectures/` should stay aligned with the public repo unless there is an intentional private-only reason to diverge.

### Syncing changes from the public repo

When someone pushes updates to the public student repository (new lecture examples, fixed typos, updated notes), pull them into the teacher repo:

```bash
git fetch upstream
git merge upstream/main
git push origin main
```

Conflicts are rare — they can only happen if the same README was edited in both repos. If a conflict occurs, keep the teacher version (it includes teacher references that the public version doesn't have).

Protect the private teacher layer during merges:

- keep the teacher versions of `README.md`, `AGENTS.md`, `quizzes/`, `docs/publishing-model.md`, and `docs/repository-overview.md`
- merge shared lecture improvements from `upstream` into `lectures/`, `docs/student-quickstart.md`, and other student-facing files as needed
- if a root-level doc changes in both repos, manually re-apply any useful public improvements instead of overwriting the teacher copy

### Making teacher-only changes

Edit teacher notebooks or cheat sheets directly in this repo and push:

```bash
git add -A
git commit -m "update L05 teacher cheat sheet"
git push origin main
```

These changes stay private and will never conflict with upstream merges.

### Making changes to shared content

If you need to fix a student notebook, lecture notes, or slides:

1. **Make the change in the public repo first** (`machine_learning_course_basics`), commit, push.
2. Then sync here: `git fetch upstream && git merge upstream/main && git push origin main`.

This keeps the public repo as the single source of truth for student-facing content.
